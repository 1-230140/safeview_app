# SafeView Warehouse Scanner

The final detection path offers two models trained only from the 52 original warehouse
images and training-only derivatives:

- `models/fasterrcnn-warehouse-v3-best.pt`: Faster R-CNN ResNet50 FPN v2, the
  accuracy-focused option.
- `models/yolov10-warehouse-best.pt`: YOLOv10n, the speed-focused option.

Both recognize cardboard boxes, forklifts, safety cones, and safety vests. The former
YOLOv8 PPE model is not part of the app detection path.

Default login: `admin / safeview2025`.

## Run locally
on powershell
  cd "path file of the downloaded clone"
  1st powershell terminal
1. Install backend dependencies: `.venv\Scripts\python.exe -m pip install -r backend\requirements.txt`
2. Start the model API: `.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8001`
   2nd powershell terminal
3. In another terminal, serve this folder on port 8000: `.venv\Scripts\python.exe -m http.server 8000`
4. Open `http://localhost:8000`.

The local model checkpoint is intentionally ignored by Git. This is an academic prototype;
its five-image test evaluation is too small for operational safety decisions.

## Final Evaluation Evidence

Run the following in the Kaggle GPU session that contains the final YOLOv10 checkpoint
and the untouched `test` split. It performs the equivalent of
`yolo val model=best.pt data=data.yaml split=test`, saves the validation plots, records
precision/recall/mAP, re-measures end-to-end inference speed after warm-up, captures peak
GPU allocation, and records the Kaggle machine information.

```bash
python tools/measure_yolov10_final.py \
  --model /kaggle/working/yolov10-warehouse-best.pt \
  --data /kaggle/working/warehouse_yolov10_2625/data.yaml \
  --output /kaggle/working/yolov10-final-evidence
```

Save these artifacts with the thesis materials:

- `yolov10-final-summary.json` for the final test metrics, re-measured speed, GPU memory,
  and training-machine specification.
- the `test/` directory generated by Ultralytics for validation plots and confusion matrix.
- `yolov10-test-results.csv` when Ultralytics produced a `results.csv` for the run.

The six-scenario comparison must use the same five untouched test images and the same
confidence/IoU policy for both models. The existing Faster R-CNN robustness measurements
are baseline RGB F1=0.343, slant/perspective F1=0.435, color/brightness F1=0.462,
grayscale F1=0.400, Gaussian blur F1=0.389, and Canny stress test F1=0.000. These values
are not a YOLOv10 comparison until the final YOLOv10 checkpoint is measured against the
identical transformed test images.

To generate the paired table from the final checkpoints, run this in Kaggle. It applies
baseline RGB, slant/rotation, color/brightness, grayscale, Gaussian blur, and Canny edge
to the same untouched test images and saves micro precision, recall, and F1 for each model.

```bash
python tools/compare_six_scenarios.py \
  --dataset /kaggle/working/warehouse_yolov10_2625 \
  --faster-rcnn /kaggle/input/your-models/fasterrcnn-warehouse-v3-best.pt \
  --yolov10 /kaggle/working/yolov10-warehouse-best.pt \
  --output /kaggle/working/six-scenario-comparison.csv \
  --confidence 0.25 --iou 0.50
```

Record the selected confidence threshold in the thesis. The command intentionally uses
one threshold for both models so the comparison is fair; it may differ from the separate
threshold that gives either model its best standalone F1.

For the retraining claim, preserve the training cell that initializes from
`YOLO("yolov10n.pt")` (pretrained weights), rather than `YOLO("yolov10n.yaml")` (a new
architecture without pretrained weights), plus the console output showing transferred
weights. A final `best.pt` alone does not prove how it was initialized.
